# 비조치 트랙 baseline — 순환 없는 평가

## 왜 이 트랙인가

LLM 분류기를 LLM 이 만든 정답으로 채점하면 **순환 평가**다. 면접에서 정확히 그 지점을
공격당한다 — "정답을 만든 모델로 정답을 맞히는 게 무슨 의미가 있나요?"

비조치의견서는 그 문제가 없다. 결론이 **금융감독원이 문서 헤더 체크박스에 직접 찍은
것**이고, 어떤 모델도 개입하지 않았다. 이 프로젝트에서 순환 없는 정답을 가진 유일한
자산이다.

| | |
|---|---|
| 과제 | 요청대상행위만 보고 결론 예측 |
| 라벨 | 비조치 / 조치 / 기타 (문서 체크박스) |
| dev | 85건 — 규칙을 쓰며 들여다봐도 되는 몫 |
| test | 170건 — 끝까지 건드리지 않는다 |

**한계도 함께 적는다.** 이 트랙은 법령해석 분류기의 성능을 직접 증명하지 못한다.
과제가 다르다(요청대상행위 → 결론 vs 회답 → 결론). "전이될 것"이라는 가정이 들어가며,
법령해석 숫자가 필요해지면 **미리 채우지 않은 백지 상태로** 사람이 라벨링하는 것이
유일하게 깨끗한 경로다. 미리 채워 두고 검수하게 하면 앵커링이 걸려 거의 그대로
승인하게 되고, 라벨링 비용만 쓰고 독립성은 얻지 못한다.

## 정답 누출을 세 번 걷어냈다

### 1. `판단이유` 는 입력에서 통째로 뺐다

| 항목 | 결론 문구 포함 |
|---|---|
| 요청대상행위 | 17 / 255 (6.7%) |
| 판단 | 45 / 254 (17.7%) |
| **판단이유** | **145 / 252 (57.5%)** |

`판단이유` 를 넣고 정확도를 재면 모델 성능이 아니라 **문자열 복사 능력**을 재게 된다.
입력은 `요청대상행위` 하나로 고정했다.

### 2. 낱말 "비조치" 자체가 누출이었다

dev 의 클래스 전용 어휘를 뽑아 보니 비조치 클래스 상위에 낱말 `비조치를` 이 6회
남아 있었다. 처음 마스킹은 "비조치의견을 제시" 같은 **구**만 잡았기 때문이다.

신청인은 어느 건이든 비조치를 요청하므로 이 낱말은 원리적으로 결론을 가릴 정보를
주지 못한다. 그런데도 클래스별 출현이 갈린다면 그것은 신호가 아니라 누출이다.
낱말 단위로 가리도록 고쳤다.

### 3. 마스크 토큰이 새 누출이 됐다

`[결론표현]` 으로 치환했더니 그 토큰이 비조치 클래스에서만 **23회**, 다른 클래스에서
0회 나타났다. **무엇을 가렸다는 사실을 남기면 "이 요청문에 그 낱말이 있었다"는 정보가
그대로 보존된다.** 치환이 아니라 삭제로 바꾸고, 뒤따르는 조사까지 함께 지웠다
("비조치를 요청" → 낱말만 지우면 "를요청" 이라는 흔적이 다시 신호가 된다).

세 번을 걷어낸 뒤 남은 비조치 특징어는 `대주단`, `자율협약`, `저축은행` 같은
**주제어**다. 부동산PF 관련 일괄 비조치 사안들에서 온 것으로, 이것은 누출이 아니라
진짜 신호다.

## 결과 (test 170건)

| baseline | 정확도 | **매크로 F1** |
|---|---|---|
| majority (무조건 비조치) | 74.1% | **0.284** |
| keyword (dev 어휘 규칙) | 74.7% | **0.494** |

라벨별 (keyword):

| 라벨 | 지원 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 비조치 | 126 | 0.780 | 0.929 | 0.848 |
| 조치 | 14 | 0.357 | 0.357 | 0.357 |
| 기타 | 30 | 0.833 | 0.167 | 0.278 |

### 정확도는 이 과제에서 쓸 수 없는 지표다

**정확도는 0.6%p 올랐는데 매크로 F1 은 0.284 → 0.494 로 74% 올랐다.**

test 의 74.1%가 비조치이므로 아무 생각 없이 찍어도 74%가 나온다. 그 상태의 매크로
F1 은 0.284다 — 소수 클래스 둘의 F1 이 정확히 0이기 때문이다. 정확도만 보고하면
"아무것도 못 하는 분류기"와 "소수 클래스를 절반쯤 잡는 분류기"가 같은 점수로 보인다.

**LLM 이 넘어야 할 선은 정확도 74.7%가 아니라 매크로 F1 0.494 다.**

## 이 과제는 원래 어렵다

dev 에서 클래스 전용 어휘를 뽑으면 `조치` 쪽은 3회짜리 낱말 두 개가 전부이고,
test 에서는 아예 없다. 세 클래스의 요청문은 형태가 거의 같다.

```
"~하는 것이 ~에 해당하는지 여부"
```

결론은 요청문의 표면이 아니라 **법적 분석의 결과**다. 표면 어휘로 가를 수 있는 것이
거의 없다는 뜻이며, 그래서 `기타` 재현율이 0.167 에 그친다(정밀도는 0.833 — 규칙이
정확하긴 한데 거의 아무것도 못 잡는다).

이것은 baseline 이 부실해서가 아니라 **과제 자체의 성질**이다. 그리고 바로 이 지점이
LLM 에게 물어볼 가치가 있는 이유다. LLM 도 못 하면, 그 사실 자체가 결과다 —
"요청문만으로는 규제당국의 판단을 예측할 수 없다" 는 것도 측정된 발견이다.

## 재현

```bash
python scripts/make_nonaction_gold.py --input data/processed/cases_nonaction.jsonl \
    --output data/eval
for s in majority keyword; do
  python scripts/baseline_nonaction.py --gold data/eval/nonaction_test.jsonl \
      --output data/processed/pred_nonaction_$s.jsonl --strategy $s
  python scripts/evaluate.py --gold data/eval/nonaction_test.jsonl \
      --pred data/processed/pred_nonaction_$s.jsonl --labels nonaction \
      --name nonaction-$s --report experiments/results/nonaction_$s.json
done
```
