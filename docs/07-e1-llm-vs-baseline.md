# E1 — LLM vs 규칙 baseline (비조치 트랙)

과제: 요청대상행위만 보고 당국의 결론(비조치/조치/기타)을 예측한다.
정답은 금융감독원이 문서 체크박스에 찍은 것이므로 **순환 평가가 아니다.**

| | |
|---|---|
| 평가셋 | test 170건 (dev 85건은 규칙 작성에만 사용, test 는 열지 않음) |
| 모델 | `claude-opus-5`, adaptive thinking, structured outputs, effort=medium |
| 비용 | $1.878 / 170건 (건당 $0.011) |
| 실패 | 0건 |

## 결과

| 모델 | 정확도 | 매크로 F1 | 95% CI |
|---|---|---|---|
| majority (무조건 비조치) | 74.1% | 0.284 | 0.269–0.296 |
| keyword (dev 어휘 규칙) | 74.7% | 0.494 | 0.385–0.592 |
| **LLM** | **78.8%** | **0.587** | 0.468–0.691 |

라벨별 (LLM):

| 라벨 | 지원 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 비조치 | 126 | 0.836 | 0.929 | 0.880 |
| 조치 | 14 | 0.667 | 0.286 | 0.400 |
| 기타 | 30 | 0.542 | 0.433 | 0.481 |

## LLM 이 규칙보다 낫다고 말할 수 없다

점추정만 보면 0.587 > 0.494 이니 이겼다고 쓰고 싶어진다. **그렇게 쓰면 안 된다.**

각 모델의 신뢰구간을 따로 그려 놓고 비교하는 것도 틀렸다. 두 모델은 같은 사례를
채점하므로 오차가 상관되어 있다. 같은 재표본에서 두 모델을 동시에 채점하고
**차이의 분포**를 봐야 한다 (대응표본 부트스트랩, 5,000회).

| 비교 | 차이 | 95% CI | p(근사) | 판정 |
|---|---|---|---|---|
| keyword − majority | +0.210 | +0.096 – +0.312 | 0.000 | **유의** |
| LLM − majority | +0.303 | +0.182 – +0.412 | 0.000 | **유의** |
| **LLM − keyword** | **+0.093** | **−0.061 – +0.247** | **0.241** | **판정 보류** |

**둘 다 majority 는 확실히 이기지만, LLM 과 규칙 사이는 n=170 에서 가릴 수 없다.**
소수 클래스가 조치 14건 · 기타 30건뿐이라 검정력이 부족하다.

이 결론을 뒤집으려면 test 를 키우는 수밖에 없다. 사례집을 더 확보하거나,
dev 85건을 test 로 합치고 규칙을 재작성하는 것(단, 그러면 규칙이 test 를 본 셈이
되므로 규칙 쪽을 다시 만들어야 한다).

## 진짜 발견 — 신뢰도가 보정되어 있다

모델에게 라벨과 함께 `confidence` 를 내게 했다. 그것이 실제 정확도와 단조로
일치한다.

| 신뢰도 | 건수 | 정확도 |
|---|---|---|
| high | 23 | 95.7% |
| medium | 101 | 88.1% |
| **low** | **46** | **50.0%** |

`low` 46건의 정확도 50%는 3지선다에서 동전 던지기 수준이다. **모델이 자기가
모르는 것을 알고 있다.**

낮은 신뢰도를 판단유보로 돌리면 운영점이 이렇게 갈린다.

| 채택 범위 | 커버리지 | 정확도 | 매크로 F1 |
|---|---|---|---|
| high 만 | 13.5% | 95.7% | 0.489 |
| **high + medium** | **72.9%** | **89.5%** | **0.819** |
| 전부 | 100.0% | 78.8% | 0.587 |

**`low` 를 버리는 것만으로 매크로 F1 이 0.587 → 0.819 로 오른다.** 답을 더 잘
맞히려고 애쓰는 것보다, 언제 답하지 말아야 하는지를 아는 쪽이 성능에 훨씬 크게
기여한다. 이 프로젝트의 문제의식이 데이터로 확인된 지점이다.

> **주의 — 이 0.819 는 전수 지표가 아니다.** 모델이 자신 있다고 고른 124건에서만
> 잰 **선택적(selective) 지표**이며, 반드시 커버리지와 함께 읽어야 한다.
> 규칙 baseline 에는 판단유보 장치가 없으므로 0.819 와 0.494 를 나란히 놓는 것도
> 공정하지 않다. 공정한 비교를 하려면 규칙 쪽에도 기권 기준을 만들어
> 위험-커버리지 곡선을 그려야 한다. 다음 실험 항목이다.

## 인용 검증 — 환각은 없었으나 "연속성"을 지어냈다

모델에게 판단 근거가 된 원문 구절을 **그대로** 인용하게 하고, 코드가 원문과 글자
단위로 대조했다.

```
인용 미대조 4건 (2.4%)
원문과의 최장 연속 일치: 93%, 90%, 67%, 54%
거의 통째로 지어낸 것(30% 미만): 0건
조각을 이어붙인 것: 4건
```

**내용을 지어낸 사례는 없다.** 4건 모두 원문에 있는 문구인데, 떨어져 있는 조각을
이어붙여 **원문에 존재하지 않는 연속 구절**을 만들었다. 예를 들어
`｢주택임대차보호법 시행령｣(이하 '시행령') 일부개정령안…` 에서 가운데를 건너뛰고
`시행령｣ 일부개정령안…` 으로 붙였다.

처음에는 검사가 지나치게 엄격한 줄 알고 따옴표·괄호 표기를 통일해 다시 대조해
봤지만 결과는 같았다. **검사가 옳았다.** 이 실패 유형은 내용 환각과 성격이 다르므로
불리언 대신 최장 연속 일치 비율을 함께 기록하도록 바꿨다.

## 업권별

| 업권 | 건수 | 정확도 |
|---|---|---|

| 가상자산 | 8 | 100.0% |
| 여신전문금융업 | 11 | 90.9% |
| 자본시장 | 12 | 83.3% |

전자금융이 37건으로 두 번째로 큰데 정확도가 가장 낮다. 혼동 사례를 보면
`전자금융감독규정` 위반 여부 질의가 몰려 있고, `기타 → 비조치` 16건 중 다수가
여기서 나온다. 이 업권만 따로 프롬프트를 손볼 여지가 있다.

## 재현

```bash
python3 scripts/classify_llm.py --task nonaction \
    --input data/eval/nonaction_test.jsonl \
    --output data/processed/pred_nonaction_llm.jsonl

for s in majority keyword llm; do
  python3 scripts/evaluate.py --gold data/eval/nonaction_test.jsonl \
      --pred data/processed/pred_nonaction_$s.jsonl --labels nonaction \
      --name $s --report experiments/results/e1_nonaction_$s.json
done

python3 scripts/compare_models.py --gold data/eval/nonaction_test.jsonl \
    --labels nonaction \
    --pred majority=data/processed/pred_nonaction_majority.jsonl \
    --pred keyword=data/processed/pred_nonaction_keyword.jsonl \
    --pred llm=data/processed/pred_nonaction_llm.jsonl \
    --report experiments/results/e1_comparison.json

python3 scripts/error_analysis.py --gold data/eval/nonaction_test.jsonl \
    --pred data/processed/pred_nonaction_llm.jsonl --labels nonaction
```
