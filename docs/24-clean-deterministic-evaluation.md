# clean split 위의 결정론 평가 (Phase B-2a)

**API 0회.** 이 문서의 수치는 전부 결정론적 코드와 검색기에서 나왔다. LLM 은
한 번도 부르지 않았고 E7~E11b 를 재실행하지 않았다.

`docs/23` 이 만든 clean split 을 **처음으로 여는 단계**다. 여는 순서를 지켰다 —
Phase B-1 에서 clean dev 로 보정표와 규칙을 뽑아 두고(`docs/23 §8`), 여기서
비로소 clean test 를 본다. test 를 보고 무엇도 고르지 않았다.

    입력   nonaction_dev_clean.jsonl 87 · nonaction_test_clean.jsonl 168
           trap_risk_clean.json · e6_rules_clean.json · cases_nonaction 256건
    산출   experiments/results/clean/   (legacy 산출물은 손대지 않았다)
    구현   app/evaluation/clean_profile.py · scripts/clean_profile.py

## 0. 먼저 — legacy 와의 비교를 어디까지 믿을 수 있는가

이 문서는 legacy 수치를 여러 번 나란히 놓는다. **그것을 "누수를 걷어낸
차이"로 읽으면 틀린다.** 두 가지가 동시에 달라졌기 때문이다.

    ① 누수가 사라졌다        test 27건이 갖고 있던 dev 쌍둥이 선례가 없다
    ② test 집합 자체가 다르다  170건 -> 168건, 그중 114건만 같은 행이다

그리고 셋째가 있다. **legacy dev 85건 중 54건이 지금 clean test 안에 있다.**

    clean test 168건 중 legacy dev 에 있던 행   54건 (32.1%)
    clean dev  87건 중 legacy dev 에 있던 행   31건

`DOUBT`·`TRUST`·`RISK_CEILING`·`MIN_AGREEMENT`·`MAX_YEAR_GAP`, 그리고 keyword
baseline 의 어휘는 **전부 legacy dev 에서 정해진 값**이다. 이 단계에서 그것을
다시 뽑지 말라는 것이 지시였으므로 그대로 물려받았고, 그 결과 **clean test 의
32%에 대해서는 문턱이 여전히 오염돼 있다.** 씻긴 척하지 않기 위해 첫 절에
적는다. 선례 풀의 누수는 사라졌지만 **초매개변수의 누수는 남아 있다.**

## 5. Router — `R1~R10` 이 몇 번 발화했나

**정책을 바꾸지 않았다.** 입력만 clean 자산으로 바꿔 결정론 워크플로를 한 번
돌렸다(`app.agents.experiments.run_variant("router")`). 모델은 관여하지 않는다.

    R1 59 · R2 21 · R3 40 · R5 27 · R6  2 · R8 19
    R4  0 · R7  0 · R9  0 · R10 0
    경로  A(선례) 19 · B(규칙) 58 · C(기권) 91

`R4` 의 0 은 예상된 것이다 — 도달할 수 없어 **이미 지운 줄**이다. 나머지
셋은 다르다. **`R7`·`R9`·`R10` 은 살아 있는 줄인데 168건에서 한 번도 발화하지
않았다.** `R10` 은 Phase A 에서 이미 표시해 둔 항목이고, 여기서 `R7`·`R9` 가
합류했다. 지금은 Router 를 건드리지 않는다.

기권 사유는 경로와 정확히 맞아떨어진다.

    CONFLICTING_EVIDENCE 61 = R1 59 + R6 2
    NO_EVIDENCE          21 = R2 21
    SURFACE_ONLY          9 = R5 중 규칙이 하나도 안 걸린 9건

### 5.1 legacy 규칙에서 clean 규칙으로 바꾸면 무엇이 움직이는가

Phase A 는 **같은 clean split·같은 clean 보정 위에 legacy E6 규칙**을 얹고
경로를 셌다(`docs/23 §7`). 그때와 지금의 차이는 **규칙 파일 하나**뿐이다.

| | legacy 규칙 (Phase A) | **clean 규칙 (지금)** |
|---|---|---|
| R1 규칙 충돌 | 44 | **59** |
| R2 근거 없음 | 42 | **21** |
| R3 선례 미달 → 규칙 | 36 | **40** |
| R5 함정 위험 → 규칙 | 25 | **27** |
| R6 / R8 | 2 / 19 | 2 / 19 |
| 기권 | 90 / 168 | **91 / 168** |

읽는 법은 이렇다. clean 규칙은 훨씬 자주 걸리므로 **"근거가 아예 없다"(R2)가
21건으로 반토막** 났다. 그런데 자주 걸린다는 것은 **서로 다른 라벨을 가리키는
규칙이 동시에 걸린다**는 뜻이기도 해서 **충돌 기권(R1)이 44→59** 로 늘었다.
둘이 거의 상쇄되어 총 기권은 90→91 로 제자리다. `R8`(선례 경로)은 규칙과
무관하므로 19 로 동일하다 — 기대한 대로다.

### 5.2 답한 것과 기권한 것

    답변 77 / 168 = 45.8%        기권 91
    답한 것 정확도 0.831   [0.732, 0.899]      맞힘 64 · 틀림 13
    답한 것 매크로 F1 0.430
    기권 91건 중 답했다면 맞았을 것 59건 (64.8%)

(참고) legacy split·legacy 자산의 Router 는 커버리지 54.1%, 답한 것 정확도
0.837, 답한 것 매크로 F1 0.609 였다(`e8_e11_agent.json`). **정확도는 거의 같고
커버리지와 매크로 F1 이 내려갔다.** 매크로 F1 이 내려간 자리는 아래 §7 이 짚는
소수 클래스다.

라벨별로 보면 이렇다.

| 라벨 | n | 답변 | 맞힘 | 틀림 | 기권 | 기권 중 맞았을 것 |
|---|---|---|---|---|---|---|
| 비조치 | 121 | 64 | 60 | 4 | 57 | 44 |
| 기타 | 33 | 12 | 4 | 8 | 21 | 8 |

### 5.3 구간별

| 구간 | n | 맞힘 | 틀림 | 기권 | 답한 것 정확도 | 95% CI |
|---|---|---|---|---|---|---|
| 순응 | 48 | 32 | 2 | 14 | 0.941 | 0.809 – 0.984 |
| **함정** | **12** | **0** | **3** | **9** | **0.000** | 0.000 – 0.562 |
| 선례 없음 | 108 | 32 | 8 | 68 | 0.800 | 0.652 – 0.895 |

함정 12건에서 **맞힌 것이 0건**이다. legacy 에서는 15건 중 2건이었다
(0.133). n=12 이고 신뢰구간이 [0.000, 0.562] 이므로 **"더 나빠졌다"고 말할 수
있는 수가 아니다.** 말할 수 있는 것은 하나다 — 표면선례 함정은 clean split
에서도 결정론 계층이 풀지 못한다.

## 6. E6 규칙의 전이 — 여기서 가장 큰 것이 나왔다

**규칙을 고치거나 다시 유도하지 않았다.** `e6_rules_clean.json` 을 그대로 읽어
발화 수와 정밀도만 셌다(`induction.measure_on` 과 같은 규칙 — 먼저 걸린 것이
이긴다).

### 6.1 먼저, 규칙을 읽는 주체가 둘이라는 것

| | 발화 | 커버리지 | 발화 시 정밀도 | 기본 라벨로 | 전체 정확도 |
|---|---|---|---|---|---|
| 유도기 의미(`Atom.holds`) | 150 / 168 | 89.3% | 0.640 [0.561, 0.712] | 18 | **0.589** |
| **Router 의미**(`rule_matches`) | 138 / 168 | 82.1% | 0.725 [0.645, 0.792] | 30 | **0.631** |

두 줄이 다른 이유는 **버그에 가까운 비대칭** 때문이다.
`app/agents/workflow.rule_matches()` 는 `ngram` 과 `length` 만 판정하고
**그 밖의 조건 종류는 무조건 `False`** 로 떨어뜨린다. clean 규칙 8번
`업권이 '공통' -> 기타` 는 `sector` 조건이므로 **Router 안에서는 영원히
발화하지 않는다.** legacy 규칙에는 `sector` 조건이 없어서 드러나지 않았던
차이다.

    유도기가 보면   8번 규칙 test 발화 22건 · 정밀도 0.18
    Router 가 보면  8번 규칙 test 발화  0건

이것은 **production 코드의 결함**이다. 이번 단계에서 Router 를 고치는 것은
금지돼 있으므로 **고치지 않았고**, 대신 두 의미를 따로 재서 간극을 수치로
남겼다. 회귀 테스트로도 박아 두었다
(`tests/unit/test_clean_profile.py::TestRuleSemantics`).

### 6.2 규칙별 전이 — dev 정밀도는 test 를 예고하지 못했다

유도기 의미 기준이다.

| # | 라벨 | dev 피복/정밀 | **test 피복/정밀** | 조건 |
|---|---|---|---|---|
| 1 | 비조치 | 22 / 1.00 | 33 / **0.91** | '에따른' AND '제1항' |
| 2 | 비조치 | 10 / 1.00 | 12 / **1.00** | '’24.' |
| 3 | 비조치 | 9 / 1.00 | 4 / **1.00** | '조치를' |
| 4 | 비조치 | 7 / 1.00 | 23 / **0.65** | '<별표' |
| 5 | 비조치 | 4 / 1.00 | 3 / **1.00** | '□가상자산사업자가' |
| 6 | 기타 | 4 / 1.00 | 15 / **0.53** | '서비스' AND '□금융회사' |
| 7 | 조치 | 6 / 1.00 | 13 / **0.38** | '위반인지' |
| 8 | 기타 | 6 / 1.00 | 22 / **0.18** | 업권이 '공통' |
| 9 | 비조치 | 5 / 1.00 | 12 / **0.92** | '에따른' |
| 10 | 기타 | 5 / 0.80 | 11 / **0.27** | '는경우' |
| 11 | 비조치 | 5 / 0.80 | 2 / **0.50** | '감독규정' |

**dev 정밀도 1.00 짜리가 test 에서 0.18 까지 내려간다.** 8번이 가장 극적이다 —
dev 에서 `공통` 업권 행 36건 중 앞선 규칙들이 안 가져간 6건만 이 규칙에
닿았고 그 6건이 전부 `기타` 였다. test 에서는 같은 조건에 22건이 닿았고
4건만 `기타` 였다. **규칙이 배운 것은 "공통 업권은 기타" 가 아니라 "앞선 일곱
규칙을 피해 간 공통 업권 6건은 기타" 였다.**

기본 라벨로 떨어진 18건 중 맞은 것은 3건이다(기본 라벨 `기타`, 남은 18건은
비조치 14 · 기타 3 · 조치 1). Phase B-1 에서 "기본 라벨은 4건이 정한 것" 이라고
적어 둔 그 값이 test 에서 18건을 받아 3건을 맞혔다.

### 6.3 legacy 와 나란히

같은 함수로 legacy 규칙을 legacy test 에 돌려 대조했다.

| | 커버리지 | 발화 시 정밀도 | 전체 정확도 | 그 split 의 다수 클래스 |
|---|---|---|---|---|
| legacy 규칙 → legacy test | 71.2% | 0.793 | 0.724 | 0.741 |
| clean 규칙 → clean test | 89.3% | 0.640 | **0.589** | 0.720 |

**legacy 에서도 규칙 모델은 이미 다수 클래스 기준선 아래였다**(0.724 < 0.741).
clean 에서는 그 간극이 훨씬 커진다(0.589 < 0.720). Phase B-1 에서 "dev 피복이
83.5%→95.4% 로 올라간 것은 자기 dev 에 대한 적합" 이라고 적어 두었는데,
**test 가 그 말을 확인해 주었다.** 더 많이 덮고 더 많이 틀린다.

여기서 결론을 하나만 확정한다. **n-gram 규칙 유도기는 이 과제에서 다수 클래스
기준선을 넘지 못한다.** 이것은 clean split 이 새로 만든 사실이 아니라 legacy
에서도 참이었던 사실이며, clean split 은 그것을 더 분명하게 보여 준 것이다.

## 7. `조치` 14건은 어디까지 평가되는가

이 코퍼스에서 가장 비싼 오류가 여기 있고, 전체 평균은 `비조치` 121건이
끌고 가므로 따로 센다.

    문턱 위 선례를 가진 것       1 / 14   (그 1건은 top-1 라벨이 기타 — 함정)
    top-1 라벨이 조치인 것       3 / 14   (셋 다 문턱 아래: 0.057 · 0.133 · 0.091)
    Router 가 답한 것            1 / 14   -> 기타 로 답했고 틀렸다 (230055)
    기권                        13 / 14
    기권 중 잠정 답이 맞았던 것   7 / 13

경로는 `R1` 10 · `R2` 3 · `R3` 1 이다. **`조치` 14건 중 10건이 규칙 충돌로
