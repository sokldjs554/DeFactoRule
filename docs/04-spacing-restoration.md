# 띄어쓰기 복원

비조치의견서 PDF 45건은 한글 사이 공백이 통째로 사라진 채 추출된다.

```
금융위원회및금융감독원은｢개인금융채권의관리및개인금융채무자의보호에관한법률｣상...
```

이대로 토크나이저에 넣으면 어절 경계가 사라져 다운스트림이 전부 망가진다.

## 접근 — 외부 모델 대신 이 코퍼스로 학습

정상 추출된 사례에 82만여 자가 있고, 그것은 복원 대상과 **같은 문서군·같은 문체·같은
법령 용어**를 쓴다. 범용 띄어쓰기 모델을 가져오는 것보다 도메인이 정확히 일치하며,
학습·평가·적용이 전부 저장소 안에서 재현된다.

모델은 경계 문맥 n-gram 의 공백 출현 빈도를 센다. 글자 사이 각 위치마다 경계를 걸치는
문맥 6종(1_1, 2_1, 1_2, 2_2, 3_2, 2_3)을 뽑아 로그 오즈를 평균한다. 학습 코퍼스에서
3회 미만 등장한 문맥은 버린다. 문맥 203,265개, 5.5 MB.

## 결과

| 대상 | F1 | 정밀도 | 재현율 |
|---|---|---|---|
| **비조치의견서 (실제 적용 대상)** | **0.816** | 0.807 | 0.825 |
| 법령해석 회신문 | 0.874 | 0.897 | 0.850 |
| 전체 평균 | 0.855 | — | — |

임계값 −0.25. 보류 105건(전체의 1/10, 결정론적 분할)으로 측정했다.

```
복원 전  □코로나19 펜데믹의후유증으로이례적인고금리·고물가가지속되는등예외적인
복원 후  □ 코로나19 펜데믹의 후유증으로 이례적인 고금리·고물가 가지속되는 등예외적인
```

## 개발 중 잡은 것 — 지표가 버그와 함께 일관되면 지표는 거짓말을 한다

### 1. 경계 라벨이 한 칸 밀렸다

`iter_boundaries` 는 공백을 만나면 `labels[-1] = 1` 로 표시했다. 그러나 그것은 다가올
경계가 아니라 **직전** 경계다. 모든 라벨이 한 칸 왼쪽으로 밀렸다.

문제는 **학습과 평가가 같은 함수를 썼다는 점**이다. 밀린 라벨로 배우고 밀린 라벨로
채점하니 F1 0.79 가 나왔다. 지표만 보면 정상이다. 출력을 눈으로 보고서야 드러났다.

```
후유증으 로     (정답: 후유증으로)
것 이           (정답: 것이)
코로나1 9펜데믹  (정답: 코로나19 펜데믹)
```

전부 정확히 한 칸씩 앞이다. 고친 뒤 비조치 F1 0.786 → **0.816**.

이 버그는 단위 테스트로 못박았다 (`test_boundary_labels_are_not_shifted`,
`test_roundtrip_labels_reconstruct_original`). 라벨로 원문을 되짚어 복원할 수 있는지
검사하면 이런 밀림은 통과할 수 없다.

### 2. 평가 표본이 적용 대상과 달랐다

처음에는 전체 평균 F1 **0.855** 를 성능으로 보고할 뻔했다. 그런데 보류 표본 105건 중
84건이 법령해석이고, **복원 대상 45건은 전부 비조치의견서**다.

두 문체는 성능이 다르다 — 법령해석 0.874, 비조치 0.816. 다수인 법령해석이 평균을
끌어올려 실제 적용 성능을 **7포인트 과대평가**하고 있었다. 문체별로 나눠 재고, 적용
대상의 숫자를 대표값으로 삼는다.

### 3. 남아 있는 공백을 지웠다

소실 표시가 붙은 사례에도 공백이 3~4% 남아 있다(숫자·문장부호 주변). 그것은 조판에서
살아남은 진짜 경계이므로 모델 예측보다 신뢰도가 높다. 처음 구현은 전부 지우고 다시
예측해 맞던 공백까지 망가뜨렸다. 지금은 **넣기만 하고 지우지 않는다**.

## 재현

```bash
python scripts/restore_spacing.py train --input data/processed --model models/spacing.json
python scripts/restore_spacing.py eval  --input data/processed --model models/spacing.json
python scripts/restore_spacing.py apply --input data/processed --model models/spacing.json --threshold -0.25
```

모델은 커밋하지 않는다(`models/` 는 `.gitignore`). 위 명령으로 재생성된다.
복원 결과는 `raw_restored` · `fields_restored` 로 원문 옆에 붙는다 — **원문을 덮어쓰지
않는다.** 복원은 추정이고, 추정이 원본을 대체하면 되돌릴 수 없다.

## 한계

- 비조치 F1 0.816 은 완벽하지 않다. `가지속되는`, `신용점 수하락` 같은 오류가 남는다.
- 복합명사 경계가 특히 약하다. 학습 코퍼스에서 함께 붙어 나오는 빈도가 높기 때문이다.
- 다운스트림에서는 `fields_restored` 를 쓰되, 근거 인용은 반드시 `fields`(원문)로
  되돌아가야 한다.

## 부록 — 텍스트 레이어가 깨진 자료

`2021년 비조치의견서 사례집` 은 파싱 결과가 **0건**이었다. 본문이 이렇게 추출된다.

```
 (ᘲ⁞♆̱⁞♆̱؞⢮)    ⭾㆗៪▫㩳⯮ □ ❂၊ࢆ19 ᷯⶓἪ၊’21.2.4.ᕮ⤞᫊
```

ToUnicode CMap 이 없는 Identity-H CID 폰트로 조판된 PDF다. 글리프가 엉뚱한 코드포인트로
뽑히며, **예외 없이 그럴듯한 길이의 쓰레기 문자열이 반환된다.** 목차와 구분 페이지만
정상인데(다른 폰트를 쓴다), 그래서 "파싱은 됐는데 사례가 0건"으로 보인다.

텍스트 추출로는 복구 불가능하고 OCR 이 필요하다. 대신 **자동 탐지**를 넣었다 —
읽을 수 있는 글자(한글 음절·자모·한자·ASCII·문장부호) 비율이 80% 미만이면
`UnreadablePdfError` 로 걷어내고 이유를 출력한다. 해당 자료는 37.4%였다.

같은 해 법령해석 회신문 사례집 154건은 정상이므로 2021년이 통째로 빠지지는 않는다.
