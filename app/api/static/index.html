DeFactoRule

금융 규제당국의 회신 이력에서, 문서 어디에도 적혀 있지 않은 판단 기준을 복원한다. 이 화면이 보여주는 것은 정확도가 아니라 모델이 자기가 틀릴 때를 아는가이다 — 실험 E2 에서 규칙과 LLM 의 매크로 F1 은 구분되지 않았고, 기권을 허용하고 나서야 갈렸다.

1. 위험–커버리지

가로축은 답한 비율, 세로축은 그중 틀린 비율. 왼쪽 아래로 내려가는 곡선이 "자신 없을 때 답을 미룰 줄 안다"는 뜻이다. 곡선이 한 점뿐인 모델은 기권 신호가 아예 없다는 뜻이며, 그 평평함 자체가 진단이다. AURC 는 위험의 평균이므로 낮을수록 좋다. 커버리지가 서로 다른 두 F1 을 나란히 놓는 것은 비교가 아니다.

2. 같은 문턱을 직접 움직여 본다

위 곡선의 운영점을 고르는 것과 아래 min_confidence 를 올리는 것은 같은 행위다. 문턱을 올리면 모델은 자신 없는 사안에서 기권한다. 기권 판정은 모델이 아니라 결정론적 코드가 한다 — 모델은 신뢰도 등급까지만 말한다.

판정을 누르면 결과가 여기 나옵니다.

3. 업권별 기저율 — 어려운 구간과 못하는 구간은 다르다

업권마다 결론 분포가 다르다. 다수 클래스 비율이 51%인 업권과 88%인 업권에서 같은 정확도는 전혀 다른 의미다. E1 에서 절대 정확도로 줄세워 진단을 틀렸고, E3 에서 바로잡았다. 표본이 적은 업권은 회색으로 표시한다 — 3건짜리 분포를 숫자로 내밀면 잡음을 신호로 위장하는 셈이다. 이 값은 dev 에서만 뽑는다.

4. 실패 레지스트리 — 고친 것이 지금도 고쳐져 있는가

실패 케이스마다 실행 가능한 재현 검사가 붙어 있고, 이 화면은 그것을 지금 돌린 결과다. 문서에 적힌 과거형 서술과 달리 여기서 실패가 뜨면 그 수정은 지금 풀려 있는 것이다.

모든 수치는 커밋된 산출물에서 계산한다. 서버가 그 자리에서 모델을 돌려 숫자를 만들지 않는다 — 이 화면의 값과 scripts/ 로 재현한 값이 다르면 그 자체가 버그다.
