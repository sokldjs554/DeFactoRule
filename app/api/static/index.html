DeFactoRule

금융 규제 회신 사례를 분류하는 과정에서 단순 정확도만으로는 모델의 차이를 확인하기 어려웠습니다. 그래서 신뢰도가 낮은 결과를 보류했을 때 오류가 얼마나 줄어드는지도 함께 비교했습니다.

1. 위험–커버리지 비교

가로축은 모델이 결과를 낸 비율이고, 세로축은 그중 틀린 비율입니다. 같은 비율만큼 결과를 냈을 때 오류가 낮은 모델이 더 안정적입니다. AURC도 낮을수록 좋습니다.

불러오는 중…

2. 신뢰도 기준 테스트

최소 신뢰도를 바꿔 결과가 어떻게 달라지는지 확인할 수 있습니다. 설정한 기준보다 신뢰도가 낮으면 결과 대신 ‘판단 보류’가 표시됩니다.

판정 결과가 여기에 표시됩니다.

3. 업권별 라벨 분포

업권마다 조치·비조치 비율이 달라서 정확도만 보면 성능을 잘못 해석할 수 있습니다. 이를 확인할 수 있도록 dev 세트의 업권별 분포를 함께 표시했습니다. 표본이 5건 미만인 업권은 전체 분포를 사용합니다.

4. 실패 사례 관리

개발 중 발견한 오류와 이를 다시 확인하는 테스트 목록입니다. 수정한 문제가 다시 발생하면 ‘재발’로 표시됩니다.

화면의 지표는 저장소에 저장된 평가 결과를 사용합니다. 페이지를 열 때 모델을 새로 실행하지 않습니다.
